## 1. ما هو المشروع

نظام إدارة مستشفيات (HMS) متعدد المستشفيات ومتعدد المنصات من قاعدة كود واحدة:

| الطبقة | التقنية | المسار |
|---|---|---|
| الواجهة | React 18 + Vite 6 + Tailwind 4 + React Query + i18next (عربي RTL / إنجليزي) + PWA | `web/` |
| الـ API | Hono 4 + Zod + `@libsql/client` (Turso أو SQLite محلي) + Argon2id | `server/` (حزمة `@hmsi/api`) |
| المشترك | الأنواع، التحقق (Zod)، الصلاحيات (RBAC) | `packages/shared/` |
| النشر | **Netlify**: الواجهة من `web/dist` + دالة `netlify/functions/hmsi.ts` على `/api/*` | `netlify.toml` |
| سطح المكتب | Tauri v2 (هيكل — لم يُبنَ فعلياً) | `tauri/src-tauri/` |
| الوثائق | المواصفات الأصلية (ناقصة: تبدأ من البند 112) + 9 ملفات معمارية | `docs/` |

### تدفق الطلب
```
المتصفح ──► web ──► lib/api.ts ─┬─ liveApi  → fetch('/api/...')   (الإنتاج: VITE_API_MODE=live في netlify.toml)
                                  └─ demoApi  → بيانات وهمية في الذاكرة (الافتراضي محلياً)
/api/* ──► Netlify Function ──► server/src/app.ts (Hono)
    securityHeaders → requireSecretOutsideLocal → ensureMigrated (تلقائي) → setUser → csrfProtection
    → routes/* → repos/* → db (libsql) ؛ الأخطاء المتوقعة HttpError → onError
```

### البيانات
`hospitals → departments → wards → beds(code)` ؛ `users(hospital_id, role)` ؛ `patients(hospital_id)` ؛
`admissions(bed, status, reason, discharge_summary, family_pin)` ؛ السجلات الطبية كلها تتبع `admission_id`.
الجلسة: `sessions(active_hospital_id)` — المستشفى الفعّال للمدير العام.
**العزل بين المستشفيات** = كل استعلام مقيّد بـ `session.user.hospital_id` (الحارس الأساسي `getAdmissionScope`).

### الأوامر
```bash
npm install
npm run dev:local        # API (:8787, قاعدة محلية) + web (:5173)
npm run typecheck        # shared + server + web
npm test                 # اختبار e2e: 180 فحصاً (قاعدة مؤقتة)
npm run build            # بناء الإنتاج

npm run db:seed:local -w @hmsi/api # بيانات تجريبية محلياً (يمسح القاعدة المحلية)
```

## 3. القرارات المعتمدة (من صاحب المشروع — 2026-09-25)

- **D1 صفحة QR:** لمتابعة **ذوي المريض** بدون تسجيل دخول.
  التطبيق: الصفحة العامة تعرض الموقع والحالة والأحرف الأولى فقط؛ الاسم الكامل والطبيب وآخر علامات حيوية
  تحتاج **رمز عائلة (6 أرقام)** يُولَّد عند التنويم ويُلغى عند الخروج. لا بيانات طبية تفصيلية أبداً.
- **D2 النشر:** Netlify (حُذفت إعدادات Vercel).
- **D3 المرفقات:** داخل قاعدة البيانات (حد 4MB بسبب حد Netlify 6MB للطلب).
- **D4 (معدّل 2026-09-25 بقرار صاحب المشروع):** مدير المستشفى (`admin`) = **كل الصلاحيات داخل مستشفاه** بما فيها السريرية؛
  المدير العام (`super_admin`) = **كل الصلاحيات** + إدارة المستشفيات، ويدخل أي مستشفى (تبديل عبر الجلسة).
  عزل المستشفيات باقٍ: كل عملية مقيّدة بالمستشفى النشط. (كان سابقاً: بدون صلاحيات سريرية.)

## 4. ما أُصلح في المراجعة الشاملة (2026-09-25)

### البناء
- ✅ كل أخطاء TypeScript في الـ server (13) والواجهة (~34) — imports ناقصة، متغيرات غير معرّفة، صياغة TrackPage، qrcode.react.
- ✅ ملفات سجلات البناء حُذفت من git، والمواصفات الأصلية أصبحت متتبَّعة: `docs/00-original-spec.md`.

### الأمان
- ✅ **عزل المستشفيات** في كل السجلات الطبية (كان `records.ts` بلا تقييد بالمستشفى).
- ✅ مدير المستشفى الجديد: كلمة المرور تُشفَّر (كانت ستُحفظ نصاً صريحاً في عمود غير موجود).
- ✅ صفحة QR: لم تعد تكشف الملف الطبي كاملاً (كانت تعطيه لأي مستخدم مسجّل حتى بدون `chart.view`).
- ✅ مدير المستشفى لا يستطيع تعديل/تعطيل حساب المدير العام، ولا أحد يغيّر دوره بنفسه.
- ✅ حماية التخمين حسب (المستخدم + العنوان) بدل قفل الحساب من أي مكان؛ العنوان من `x-nf-client-connection-ip`.
- ✅ الـ API يرفض العمل خارج localhost إذا غاب `SESSION_SECRET`؛ الكوكيز Secure على HTTPS.
- ✅ مقارنة CSRF وقت-ثابت؛ مقارنة وهمية عند عدم وجود المستخدم (لا كشف لأسماء المستخدمين).
- ✅ المرفقات: أنواع مسموحة فقط، تُنزَّل كملف دائماً باسمها الأصلي، حد 4MB.
- ✅ تنظيف الجلسات المنتهية ومحاولات الدخول القديمة؛ إنهاء الجلسات عند تغيير كلمة المرور.
- ✅ مسح ذاكرة الواجهة (React Query) عند الدخول/الخروج/تبديل المستشفى؛ الـ Service Worker لا يخزّن `/api`.
- ✅ `is_active: "false"` لم يعد يتحول إلى `true`.

### المنطق والسلوك
- ✅ الممرض يكتب ملاحظات التمريض (كان مرفوضاً 403)؛ كل نوع ملاحظة بصلاحيته؛ تعديل/حذف الملاحظة لكاتبها فقط.
- ✅ سير المختبر/الأشعة: **الطبيب يطلب** (`lab.order`/`radiology.order`) و**الفني يُدخل النتيجة**؛ خيار «نتيجة غير طبيعية».
- ✅ صفحتا المختبر والأشعة: إدخال النتيجة يُكمل الطلب نفسه (كان يُنشئ فحصاً مكرراً ويبقى الطلب معلّقاً للأبد).
- ✅ إضافة فحص من الواجهة كانت تفشل دائماً (422 بسبب `category: null`).
- ✅ تغيير حالة دواء لم يعد يمسح اسمه الإنجليزي.
- ✅ ملخص الخروج في عمود مستقل — لم يعد يمحو سبب الدخول.
- ✅ لا أوامر علاجية جديدة لتنويم منتهٍ (الملاحظات المتأخرة والنتائج مسموحة).
- ✅ التنويم/النقل/الخروج/الأرشفة/تخصيص السرير داخل **transactions**، وحجز السرير مشروط (لا حجز مزدوج).
- ✅ رقم الملف تسلسلي (كان عشوائياً من 9000 قيمة → تصادم بعد ~100 مريض).
- ✅ قسم/ردهة بدون اسم إنجليزي كان يفشل (500).
- ✅ اسم المستخدم فريد على مستوى النظام وغير حساس لحالة الأحرف.
- ✅ حالة الأسرّة في البيانات التجريبية كانت خاطئة؛ أكواد QR كانت `"null"` بعد الزرع.
- ✅ سجل التنويمات السابقة في ملف المريض (التنقل بينها).
- ✅ التقارير: التحقق من المدى (بحد أقصى سنة).
- ✅ رسائل الخطأ تظهر للمستخدم عند فشل أي عملية (كانت تفشل بصمت)؛ انتهاء الجلسة يعيد لصفحة الدخول.
- ✅ مسارات الواجهة للمستشفيات والتتبع (كانت `/api/api/...` = 404 دائماً).
- ✅ الـ migrations مضمّنة في الكود وتُطبَّق تلقائياً (كانت تُقرأ من القرص ولا تعمل على Netlify، وتُطبَّق فقط مع مسح البيانات).
- ✅ `seed` يتطلب تأكيداً صريحاً ويرفض قاعدة Turso بدون `--wipe-remote`.

### ميزات جديدة
- ✅ صفحة **المستشفيات** للمدير العام: إنشاء، تعطيل/تفعيل، إضافة مدير، الدخول كمدير، إحصاءات.
- ✅ صفحة **متابعة ذوي المريض** `/track/:code` + رمز QR قابل للطباعة لكل سرير + رمز العائلة (يظهر عند التنويم وفي رأس ملف المريض، مع زر إصدار رمز جديد).
- ✅ **تغيير كلمة المرور** (الإعدادات) و**إعادة تعيينها** من المدير (صفحة المستخدمين).

- ✅ نصوص عربية ثابتة في الكود كانت تظهر في الواجهة الإنجليزية (صفحة الدخول، «طيّ القائمة»)، وأسماء المستشفى/الردهات/المرضى/الأحداث تتبع لغة الواجهة الآن.

- ✅ أزرار «مريض جديد/تعديل/أرشفة/تنويم» كانت تظهر لمن لا يملك الصلاحية.

- ✅ الأحرف الأولى في صفحة الأهل كانت تظهر مشوّهة ← «م*** ع***».

### التمريض والطباعة والعمل دون اتصال (2026-09-25، migration 008)
- ✅ **سجل إعطاء الأدوية (MAR)**: صلاحية `medications.administer` (ممرض + طبيب). لكل دواء نشط: «تسجيل جرعة» (أُعطيت/أُجّلت/رفضها المريض — التأجيل والرفض يتطلبان سبباً)، آخر جرعة وعدد جرعات 24 ساعة، تحذير إن لم يُصرف الدواء أو سُجّلت جرعة خلال آخر ساعة. التصحيح لمسجّل الإدخال خلال ساعة فقط. دواء أُعطيت منه جرعات لا يُحذف (يُوقف).
- ✅ **سجلات التمريض**: مقياس الألم 0–10 ومستوى الوعي (AVPU) مع العلامات الحيوية؛ **ميزان السوائل** (داخل/خارج بأنواعها، مجموع 24 ساعة والصافي).
- ✅ **MEWS** (درجة الإنذار المبكر، `packages/shared/src/clinical.ts`): بطاقة للمريض مع الإجراء المقترح، عمود في جدول القراءات ومعاينة أثناء الإدخال، وبطاقة «إنذار مبكر» في لوحة التحكم لمن درجتهم ≥3 (آخر قراءة خلال 24 ساعة). أداة مساعدة — العتبات قابلة للمراجعة مع الطاقم الطبي.
- ✅ **الطباعة (A4)**: أنماط `@media print` في `tokens.css` (إخفاء التنقل والأزرار، أبيض وأسود، إطارات بدل الخلفيات، القيم غير الطبيعية بخط عريض)؛ زر «طباعة القسم» مع ترويسة ورقية (القسم، المستشفى، وقت الطباعة، الطابع). رمز العائلة لا يُطبع.
- ✅ **ملصقات الباركود**: سوار المريض (Code128 لرقم الملف) وملصق عيّنة المختبر (Code128 لمعرّف الطلب) بنسخة HTML لأي طابعة، و`GET /api/patients/:admissionId/labels/wristband` و`/labs/:id/label` بصيغة **ZPL** للطابعات الحرارية. المتصفح لا يرسل مباشرة إلى منفذ الطابعة ودالة Netlify لا ترى شبكة المستشفى؛ الإرسال المباشر يحتاج وكيل طباعة محلي (مثل Zebra Browser Print). النص العربي في ZPL يحتاج خطاً عربياً على الطابعة (`LABEL_FONT`، افتراضياً `E:ARIAL.TTF`).
- ✅ **المرفقات**: فحص توقيع الملف الفعلي (magic bytes) مقابل النوع المعلن — ملف HTML باسم `.png` يُرفض (415)؛ تحقق مماثل للحجم والنوع في الواجهة؛ التنزيل برأس `Content-Security-Policy: sandbox` و`no-store`. التخزين داخل قاعدة البيانات ولا يُقرأ إلا بجلسة + `chart.view` + نفس المستشفى.
- ✅ **العمل دون اتصال**: طابور في الواجهة (`web/src/lib/offline-queue.ts`) للعلامات الحيوية والسوائل والجرعات — يُحفظ محلياً لكل مستخدم ويُرسل عند عودة الشبكة، مع مؤشر في الشريط العلوي وقائمة بالمرفوض. إضافة إلى **Background Sync** في Service Worker (Workbox) لنفس الطلبات. كل إدخال يحمل `client_id` فلا يتكرر عند إعادة الإرسال، ووقت القياس الفعلي مقبول حتى 48 ساعة.
- ✅ بحث المرضى بالرقم الوطني ورقم الهاتف.
- ✅ `netlify.toml`: CSP أساسية (`frame-ancestors 'none'`...)، تخزين `/assets/*` سنة، `sw.js` بلا تخزين. توجيه `/api/*` يتم عبر `config.path` في الدالة — **لا تضف redirect إلى `/.netlify/functions/...`**.

## 7. قواعد العمل على المشروع

- `packages/shared` يُبنى بصيغتين: ESM (`dist`) وCommonJS (`dist-cjs`) لأن دالة Netlify تحمّله بـ `require()` — لا تحذف أياً منهما.
- ابنِ `packages/shared` قبل typecheck الـ server/web (يستوردان `dist/`) — `npm run typecheck` يفعل ذلك.
- كل repo يستقبل `hospitalId` ويقيّد به. أي مسار سجلات طبية يمر عبر `getAdmissionScope`.
- عمود جديد = ملف `server/db/migrations/00N_*.sql` جديد ثم `npm run db:gen -w @hmsi/api`. لا تعدّل migrations قديمة.
- لا تشغّل `seed` على قاعدة الإنتاج.
- نصوص الواجهة في `web/src/i18n/{ar,en}.ts` (نفس المفاتيح في الملفين — `en` مربوط بنوع `ar`).
- أي دالة API جديدة تُضاف في `api.ts` (الواجهة) و`api-live.ts` و`api-demo.ts` معاً.
- أخطاء العمل المتوقعة: `throw new HttpError(message, status)` من `server/src/lib/errors.ts`.
- أضف فحصاً في `server/scripts/smoke.ts` لكل سلوك أمني أو منطقي جديد.
